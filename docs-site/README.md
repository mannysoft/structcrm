# StructCRM documentation site

The public documentation for [StructCRM](../README.md), built with
[Docusaurus 3](https://docusaurus.io). Published to
<https://mannysoft.github.io/structcrm/> by the `Documentation` GitHub workflow.

## Local development

```bash
cd docs-site
npm install
npm run start          # http://localhost:3000/structcrm/
```

## Build

```bash
npm run build          # static output in ./build
npm run serve          # preview the production build
npm run typecheck      # validate config and sidebar types
```

`onBrokenLinks` is set to `throw`, so a broken internal link fails the build — that is the
link checker.

## Structure

```text
docs/
├── intro.md
├── getting-started/     # install, configure, seed, run
├── user-guide/          # every module from the end user's point of view
├── developer-guide/     # architecture, patterns, testing, conventions
├── api/                 # REST API reference
├── operations/          # configuration, queues, storage, deployment
└── contributing/        # contributor workflow and policies
```

Sections are autogenerated in `sidebars.ts`; page order comes from `sidebar_position` in
each page's front matter. See
[Writing documentation](https://mannysoft.github.io/structcrm/docs/contributing/documentation).

## Deployment

Pushing to `main` with changes under `docs-site/**` triggers
`.github/workflows/docs.yml`, which builds the site and deploys it to GitHub Pages.

One-time setup: in the repository, open **Settings → Pages** and set **Source** to
**GitHub Actions**.

The site is served from a project path, so `url` is `https://mannysoft.github.io` and
`baseUrl` is `/structcrm/`. If you move the site to a custom domain, update both in
`docusaurus.config.ts`.

## Note on the build pipeline

`future.v4` is enabled for forward compatibility, but the Docusaurus **Faster** native
modules (rspack/swc/lightningcss) are explicitly disabled in `docusaurus.config.ts` because
they do not load on every Node version. The site builds with the standard webpack pipeline.
